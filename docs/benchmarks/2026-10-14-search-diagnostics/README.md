# 100k substring-search diagnosis · 14 October 2026

The disposable fixture used the preceding sustained image, `mosscms:benchmark-ef04f0cc7a57`. [Fixture metadata](fixture.json) and [plans](plans.json) are retained. Three repetitions of each `EXPLAIN (ANALYZE, BUFFERS)` query were run, saving the last; there was no concurrent HTTP load. The alternatives remove the public-title `CASE` because every benchmark article title is public. The final application separately enforces current title privacy for named and untyped lists.

Plans are count/page pairs for `article-000000` (unpublished miss), `missing-needle` (absent miss), and `Live` (broad published-title match). Baseline times were 13.791/44.639 ms, 14.413/15.747 ms and 39.034/0.026 ms. A temporary covering B-tree gave 15.537/17.005, 16.145/16.832 and 11.867/0.039 ms. The chosen multicolumn published-title/slug trigram GIN index gave 2.640/2.579, 0.022/0.030 and 43.485/0.038 ms. It occupied 4,800,512 bytes before mixed load. The broad count did not improve in this experiment; short or common terms can still require scans. These isolated timings are not concurrent workload percentiles.

PostgreSQL's [pg_trgm documentation](https://www.postgresql.org/docs/17/pgtrgm.html) describes `LIKE`/`ILIKE` support, rechecks and the fallback when no useful trigrams can be extracted. A [covering B-tree](https://www.postgresql.org/docs/17/indexes-index-only-scans.html) reduces heap access but still scans candidates for unanchored substrings.

The existing timed workload generates search terms only when `turn % 5 == 1`, with `article-{turn % 100:06d}`. Those IDs also have `index % 5 == 1` and no published snapshot in this fixture, so timed search measures published-slug misses. The timed query/mix is unchanged for matched comparison. Final verification adds a known miss, a positive live slug and a broad live-title term, with plans captured outside timed load. API tests additionally cover escaped wildcard/backslash literals, short terms, Unicode, publication separation, private-title changes and workspace/token scopes. Generic-plan index tests rebuild the test index after bulk inserts, matching a populated migration build rather than an unflushed GIN pending list. Production planning and vacuum/pending-list costs remain workload-dependent.

The temporary diagnostic indexes, containers and volumes were removed. Migration 0014 installs `pg_trgm` if missing and creates separate draft and published title/slug GIN indexes on PostgreSQL. SQLite keeps its existing substring path. Downgrade removes the indexes and retains the potentially shared extension. Populated index creation is transactional and can block writes; budget a maintenance window. The migration user needs permission to install the trusted extension, or an operator must preinstall it.
